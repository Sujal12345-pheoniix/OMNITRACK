# Database

Owner: Database Architect · Status: Draft v0.1 (2026-11-16) · No schema exists yet.

## 1. Platform

PostgreSQL 16, accessed through Prisma. Migrations are generated by Prisma Migrate and may contain hand-written SQL for things Prisma cannot express (row-level security, partial indexes, check constraints).

## 2. Conventions

| Topic | Rule |
|---|---|
| Naming | Tables plural `snake_case`; columns `snake_case`; Prisma models `PascalCase` mapped with `@@map` |
| Primary keys | UUID v7, generated by the application |
| Tenancy | Every tenant-owned table has `organization_id uuid not null`, a foreign key to `organizations`, and it is the leading column of the main indexes |
| Timestamps | `created_at`, `updated_at` as `timestamptz`, stored in UTC |
| Actor columns | `created_by`, `updated_by` reference `users` where the record is user-authored |
| Deletion | Hard delete by default. Soft delete (`deleted_at`) only where a requirement needs recovery or history, decided per table |
| Money | Integer minor units plus an ISO 4217 currency column. Never floating point |
| Enumerations | PostgreSQL enums for fixed system values; lookup tables for values a tenant can configure |
| Uniqueness | Business-unique values are unique per organization, for example `unique (organization_id, email)` |
| Foreign keys | Always declared, always indexed; `on delete` behaviour chosen explicitly |
| Concurrency | `version integer` column for optimistic locking on records edited by several users |
| Personal data | Columns holding personal data are listed in a data inventory in this document as tables are added |

## 3. Row-level security

Every tenant-owned table gets, in the migration that creates it:

```sql
alter table <t> enable row level security;
alter table <t> force row level security;
create policy tenant_isolation on <t>
  using (organization_id = current_setting('app.current_org_id')::uuid)
  with check (organization_id = current_setting('app.current_org_id')::uuid);
```

Database roles:

| Role | Used by | Rights |
|---|---|---|
| `omnitrack_migrator` | Migration job only | Owns schema, runs DDL |
| `omnitrack_app` | API and workers | DML only, subject to RLS, no `BYPASSRLS` |
| `omnitrack_readonly` | Reporting, support tooling | Select only, subject to RLS |

A CI check fails if a table has an `organization_id` column but no RLS policy.

## 4. Migration rules

1. One migration per change, reviewed like code.
2. A merged migration is never edited or deleted. Fix forward with a new migration.
3. Changes are backward compatible with the previously deployed application version (expand, migrate, contract), so deployment and rollback are safe.
4. Destructive changes (drop column or table, type narrowing) need a recorded data-migration plan and Database Architect approval.
5. Large data backfills run as batched jobs, not inside a schema migration.

## 5. Audit events

`audit_events` is append-only: the application role has insert and select only. Rows hold organization, actor, action, target type and ID, request ID, IP, timestamp and a redacted before/after JSON summary. It is partitioned by month once volume justifies it.
