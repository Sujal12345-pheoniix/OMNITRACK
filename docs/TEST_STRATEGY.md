# Test Strategy

Owner: QA Director · Status: Draft v0.1 (2026-11-16)

QA verifies independently of the people who wrote the code. A result is only reported if the test was actually run; results go in [engineering/TEST_REPORT.md](../engineering/TEST_REPORT.md) with the command, date, commit and output summary.

## 1. Levels

| Level | What it proves | Tooling | Runs |
|---|---|---|---|
| Static | Types, lint, import boundaries, formatting | `tsc --noEmit`, ESLint, Prettier | Every commit |
| Unit | Business rules and policies in isolation | Vitest | Every commit |
| Integration | API + real PostgreSQL and Redis: validation, authorization, transactions, RLS | Vitest + Supertest + Testcontainers | Every pull request |
| Contract | Generated OpenAPI matches the committed snapshot | Snapshot diff | Every pull request |
| End to end | Critical user journeys in a browser | Playwright | Every pull request (smoke), nightly (full) |
| Accessibility | WCAG rules on each page | axe via Playwright | Every pull request |
| Security | Dependency, secret and static scanning; tenant-isolation suite | npm audit / OSV, gitleaks, Semgrep | Every pull request |
| Performance | NFR-PERF targets under reference load | k6 | Before each release |
| Recovery | Backup restore works within RTO | Scripted restore | Before first release, then quarterly |

Integration tests use a real database, not mocks, because row-level security, constraints and transactions are part of what is being tested.

## 2. Mandatory suites

1. **Tenant isolation.** For every tenant-scoped endpoint, a user of organization B requests a resource of organization A and must get 404. The suite enumerates routes from the router, so a new route without an isolation case fails.
2. **Authorization matrix.** For every route, each built-in role is checked against the expected allow or deny.
3. **RLS coverage.** Fails if a table with `organization_id` has no policy.
4. **Audit coverage.** Each audited action produces exactly one event with the right actor and target.

## 3. Coverage

Coverage is measured and reported, with thresholds of 80% lines for services and policies. Coverage is an indicator, not the goal; the four mandatory suites and requirement traceability matter more.

## 4. Traceability

Each functional requirement in [SRS.md](SRS.md) is referenced by ID in at least one test title. A script lists requirements with no test; the list must be empty for a phase to close.

## 5. Test data

Synthetic, generated by factories. Each integration test creates its own organizations and cleans up or runs in an isolated schema. No production data in any non-production environment.

## 6. Reference load (provisional)

50 organizations, 200 concurrent users, 500 employees and 50,000 leads in the largest organization. Revised when real usage expectations are known.

## 7. Defects

| Severity | Meaning | Release impact |
|---|---|---|
| S1 | Data loss, cross-tenant exposure, authentication bypass, system unusable | Blocks release |
| S2 | Core workflow broken with no workaround | Blocks release |
| S3 | Workflow impaired, workaround exists | Needs recorded acceptance |
| S4 | Cosmetic | Does not block |

## 8. Rules

- A failing test is fixed or the code is fixed. Skipping or deleting a test needs a written reason in the test report and QA Director approval.
- Flaky tests are quarantined with an owner and a deadline, not ignored.
- Tests never weaken a security control to pass.
